# M1 项目共识与验收标准

状态：M1 实现候选已提交开发分支；自动化验证见 [validation.md](validation.md)，部署及真实账户/客户端验收待执行。范围确认日期：2026-11-06。

## 定位

面向个人自托管的 Rust Microsoft To Do MCP 服务，部署在 VPS / Docker，供 ChatGPT 等远程 MCP 客户端使用。服务连接所有者自己的一个或多个微软账户。

## 已确认的产品决策

- 优先交付 M1，开始日常使用；附件归入 M2。
- 远程 Streamable HTTP 为主，提供 HTTPS 反向代理部署说明。
- 持久化保存任务正文和搜索索引，服务运行期间执行后台增量同步。
- 支持个人、工作/学校账户；账户凭据、数据、索引及同步游标隔离。
- 部署者自备 Microsoft 应用注册及 Client ID，项目提供逐步配置文档。
- 提供轻量管理页面，用于添加账户、查看同步状态、撤销授权。
- MCP 客户端访问服务的认证与服务访问 Microsoft Graph 的账户授权分别设计。

## 实现设计基线

以下为实现建议，具体协议、库版本及 API 语义应在开发时核验。

- 单个 Rust 服务配合 SQLite，Graph 为权威数据源。
- 查询默认使用本地缓存，返回最近成功同步时间和同步状态；调用方可请求刷新。
- 写入直接提交 Graph，成功后更新本地状态。响应丢失或超时应呈现待核对状态，核对后再决定重试，避免重复创建。
- 日常操作使用默认账户；跨账户搜索显式限定范围；修改和删除绑定具体账户及任务。
- 搜索索引覆盖中文、英文、数字及混合内容。
- 账户撤销时停止同步并清理本地凭据、缓存及索引；删除变更同步到本地；游标失效时重建同步状态。
- 管理页面使用访问认证；日志排除令牌和任务正文等敏感内容。

## M1 验收场景

1. 按文档在 VPS 上使用 Docker 部署，通过 HTTPS 连接至少一个目标远程 MCP 客户端，并验证未经授权的访问被拒绝。
2. 使用自备应用注册完成微软账户授权；添加第二账户后，默认账户选择和显式账户操作均正确，数据保持隔离。
3. 客户端能够完成清单、任务、步骤及关联资源的增删改查，设置正文、重要性、分类、日期、提醒和重复规则，完成及重新打开任务。
4. 搜索能找到不同清单中的中文标题及正文，支持混合英文、数字、状态和日期筛选；跨账户搜索遵循指定范围。
5. 微软客户端上的创建、修改、完成和删除能通过后台同步反映到查询结果；可查看最近成功同步时间并主动刷新。
6. 服务重启后保留授权、缓存及同步进度；模拟分页、限流、断网和游标失效，验证恢复路径。
7. 模拟写入成功但响应丢失，验证结果核对流程和重复创建防护；重复任务完成后的后续任务状态与微软端一致。
8. 撤销账户后，后台工作停止，本地凭据、任务数据和索引清理完成。
9. 记录启动时间、空闲内存、搜索延迟、Graph 请求数和工具响应体积，并说明测试规模和环境。

- 对目标客户端核验 MCP 授权兼容性、OAuth 流程和 HTTPS 部署配置。

- 核验日期、时区、重复任务及清空字段的 Graph 行为。
- 确定同步间隔、初始同步期间的查询行为、搜索完整性和错误返回契约。
- 许可证、最低 Rust 版本、依赖选型及性能数值目标在实现前确定。
